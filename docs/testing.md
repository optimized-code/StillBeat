# Testing

Synthetic and fake-camera tests verify that the implementation behaves as
designed. **They are not evidence of physiological accuracy.** See
docs/validation_protocol.md.

## How to run

```bash
tool/dev.sh test              # all unit + widget tests (VM)
tool/dev.sh test-web          # pipeline tests compiled to JS, in Chrome
tool/dev.sh analyze
tool/dev.sh test-integration <device-id>   # needs an emulator/device/browser
```

## Browser end-to-end check (manual script)

The production web build was served on `http://localhost:8787` and driven in
headless Chrome via the DevTools protocol with
`--use-fake-device-for-media-stream --use-file-for-fake-video-capture=<clip>`.
The clip (generated by a script, 320×240 Y4M, 30 fps, 60 s) shows a
skin-coloured ellipse whose colour is modulated at 72 BPM with pixel noise.

Observed: onboarding → home → purpose screen → `getUserMedia` → live
preview with guide → warm-up → measuring with live "72 BPM · Good" → result
"72 BPM · Good" with waveform. Afterwards no `<video>` element or live track
remained, and every network request went to `localhost:8787`.

The first run found a real defect: `Int64List` is unsupported in dart2js,
which made every window analysis throw on web. The session was correctly
rejected rather than fabricated, but the bug was silent. Fixes: plain
`List<int>` timestamps, web-safe sentinels, a guard that turns frame-pipeline
exceptions into a visible processing failure, and the Chrome test step in CI.

The in-app browser pane used for manual UI review blocks camera access; the
app showed the "Camera access needed" recovery screen as designed.

## Fixtures

All fixtures are generated deterministically in code
(`test/helpers/synthetic_signals.dart`, `test/helpers/fakes.dart`); no
third-party video, images or datasets are included. Public rPPG datasets
(UBFC-rPPG, PURE, …) are under research-only terms and must not be committed.

## Not yet tested (requires hardware)

* Android/iOS camera frame acquisition, rotation/mirroring, ML Kit boxes on
  real frames, isolate analysis timing, thermal behaviour, interruption
  handling (calls, Control Center, split-screen).
* Safari and Firefox (no `requestVideoFrameCallback` in Firefox) on real
  webcams; mobile browsers.
* Accuracy against a reference instrument (validation protocol).
